# DSH Nexus 核心功能设计规格说明

**当前范围：回到已讨论的单预设方案，功能自由装配延后。**

用户要求不再让后续装配扩展的边界问题阻塞原始目标。本文是收敛后的开发范围规格，不是实施计划。接下来按此范围制定具体任务与测试，不再逐项询问普通工程细节。

此前的装配扩展设计完整保存在 `future/2026-10-31-dsh-nexus-assembly-design.md`，不是当前实施依据。讨论记录位于 `docs/plans/2026-10-31-dsh-nexus-design.md`。

## 1. 意图与目标

在保留 DSH 模型接入、会话、权限、原生界面和插件生态的基础上，提供一套更适合模型使用的工具接口和可视化配置入口。

目标不是机械追求工具名称最少，而是减少不必要的选择、重复定义和参数负担，同时保留高质量执行所需的能力。

### 当前交付目标

- 一个插件包、一个独立 Nexus 预设，不修改原生预设。
- 完整提供已确定的文件、终端、联网、内部子 Agent 能力。
- 沿用 DSH 原生技能、结构化提问、待办和必要运行机制。
- 保留第三方插件向模型提供工具的能力，不实施全局白名单。
- 提供简洁基础提示词和真正的系统级附加提示词模块。
- 提供统一控制台与分功能子页面。
- 按步骤实现和验证完整目标，不能把只有基础文件操作的状态当作最终交付。

### 当前非目标

- 功能模块自由勾选、Nexus／原生／不提供三态选择。
- 多套功能装配方案、多 Nexus 预设，以及装配复制、删除、迁移和历史快照管理。
- 重新实现 DSH 的模型循环、会话引擎、权限系统或插件市场。
- 新增其他联网服务商；仅预留后端适配边界。
- 将用户的 Pi 全局指令文件复制到 DSH。
- 在基础提示词中固化强制规划、固定审查等工作流程。

**重要区别：延后的是功能装配，不是附加提示词模块的选择。提示词模块库、勾选和会话应用仍在当前范围。**

## 2. 关键用户场景

### 2.1 日常开发

用户创建 Nexus 会话，使用统一读取、精确编辑、终端等能力完成开发。原生重复入口不与替代工具同时出现在该会话中，其他第三方插件工具继续可用。

### 2.2 长任务与交互

Agent 执行构建或测试，可以运行后台任务、继续读取输出并停止执行。需要连续输入的程序使用显式持久终端，而普通命令之间不共享隐形状态。

### 2.3 内部协作

主 Agent 在已授权任务范围内自主委派 DSH 内部子 Agent，用户能通过原生界面查看过程并介入。主 Agent 接收结果后继续整合和验证。

### 2.4 系统提示词定制

用户在 Nexus 中管理附加提示词模块，选择默认组合，也可以应用到当前会话。选中的文本与基础提示词处于同一系统指令层，不依靠 AGENTS.md 或某条普通聊天记录维持。

## 3. 产品结构

### 3.1 同包内部模块化

一个插件包包含宿主侧逻辑与浏览器侧界面。代码按文件工具、终端、联网、子 Agent、提示词和 UI 等职责拆分，但当前不提供用户可编辑的功能装配图或动态模块加载框架。

这种组织方式用于保持维护性，并为以后装配功能预留合理边界，不提前实现装配管理本身。

### 3.2 宿主侧职责

- 提供一个 Nexus 预设，在其作用域注册核心工具和提示词贡献。
- 调用 DSH 原生文件、附件、联网、技能、子 Agent、设置与存储能力。
- 管理 Nexus 拥有的进程、终端、结果与会话级配置。
- 为控制台提供受控配置访问，不默认向模型暴露系统提示词管理能力。
- 保留权限、观察策略、会话和资源所有权等执行链，不能直接绕过它们调用底层执行函数。

### 3.3 浏览器侧职责

- 提供统一入口和分功能子页面。
- 保持主题、导航、保存反馈一致。
- 提供提示词模块管理、选择、排序及组合预览。
- 提供必要终端、子 Agent 等设置，不引入自由装配页面。
- 能复用的原生界面和设置优先复用，不重建整个产品布局。

### 3.4 逻辑数据边界

| 对象 | 职责 |
| --- | --- |
| Nexus 预设 | 固定核心能力组合和稳定预设身份 |
| 功能组件 | 包内职责边界及注册、清理逻辑，不是用户装配实体 |
| 提示词模块 | 稳定内部身份、名称和字面正文 |
| 默认提示词组合 | 选中模块及排列顺序 |
| 会话提示词状态 | 会话实际使用的文本与独立选择，支持恢复和显式应用 |
| 受管执行 | 所属会话、状态、输出和控制句柄 |
| 已获取联网结果 | 来源、实际取得的内容、范围和续读标识 |

不为当前功能引入可视化配置版本管理，也不建立泛化的装配快照数据库。

## 4. 核心工具与原生边界

| 接口 | 行为 |
| --- | --- |
| `read` | 统一读取文本和图片；内部识别类型；文本支持分页 |
| `write` | 创建文件或完整写入 |
| `edit` | 精确局部替换；同一文件支持一次提交多处修改 |
| `shell` | 统一普通、后台、持久和交互执行 |
| `web` | 统一联网入口，复用 DSH 后端 |
| `agent` | 统一内部子 Agent 委派和管理 |
| `skill` | 沿用 DSH 原生技能机制 |
| `ask_user_question` | 保留原生结构化提问 |
| `todo_write` | 保留原生待办 |

- CORE-01：核心工具不是模型可见工具数量的硬上限，不能因此屏蔽第三方插件。
- CORE-02：只在 Nexus 预设内处理被替代原生工具，不修改其他预设或宿主全局能力。
- CORE-03：文件发现和内容搜索默认交给终端，当前不新增专用 glob、grep 或混合 search 工具。
- CORE-04：原生权限、安全策略、项目指令、自动压缩等不因工具精简而被删除。
- CORE-05：需要检查第三方插件对新预设的兼容性，不能用“未封禁”代替实际验证。
- CORE-06：其他未列入替换范围的原生能力不在当前重写或新增配置入口；已有宿主或插件按自身作用域提供的贡献不额外禁用。

### 4.1 文件工具要求

- FS-01：统一 read 必须真正向支持图片的模型提供图片附件，不是只返回文件路径。
- FS-02：图片模型不支持、文件不存在或格式不可读时，明确反馈，不伪造成功。
- FS-03：文本读取保留分页和输出边界，截断时提供继续读取方式。
- FS-04：write 与 edit 保持不同职责，不为少一个名称而合并所有读写。
- FS-05：多处编辑基于同一次原始内容检查，匹配或重叠问题不能产生不明的部分修改。
- FS-06：保留先读后改、文件变化检查、原子修改和用户已有工作保护。
- FS-07：编辑已有文本时保护编码、BOM 和换行；无法可靠支持的编码明确拒绝或提示，不静默转换。

## 5. 终端要求

- SH-01：默认 Git Bash，支持显式选择 PowerShell 7。
- SH-02：普通调用是独立进程，不隐式继承上一条命令的目录、环境变量或函数。
- SH-03：需要状态保留或连续输入时，显式创建持久终端。
- SH-04：后台执行与持久终端分别表达，独立进程也可后台运行。
- SH-05：持久终端内部的目录变化不偷偷改变整个 DSH 会话工作目录。
- SH-06：完整功能包括启动、状态查询、输出续读、交互输入、停止和清理。
- SH-07：长输出保留可恢复日志，模型每次读取有边界。
- SH-08：区分启动失败、运行、正常退出、非零退出、超时、取消、停止中和确认结束。
- SH-09：不得把暂时无输出或已发送停止请求当作任务完成。
- SH-10：禁止失败后静默换 Shell 重跑；可能已有副作用时先核对再恢复。
- SH-11：明确适配 Windows，不能直接使用已注明 POSIX-only 的 dsh-bash-local 充当 Windows 后端。
- SH-12：程序路径和依赖发现不能偷偷依赖 Pi 特有 PATH；处理包含空格、中文及不同路径形式的参数。
- SH-13：普通有限命令取消后应完成相应清理；后台与交互执行的所有权及关闭行为在工具契约中明确。

## 6. 联网要求

- WEB-01：使用 DSH 现有可用的搜索和抓取后端，不要求新增第三方搜索账号、订阅或密钥。
- WEB-02：费用依现有后端规则，不把没有新增付费服务表述为任何请求绝对免费。
- WEB-03：接口覆盖搜索、获取页面、读取已获取结果和内容定位，具体字段由实施计划制定。
- WEB-04：提供来源、实际获取范围、结果标识、截断和继续读取方式。
- WEB-05：搜索摘要不伪装为已读取原文，上游缺失或截断时不宣称持有完整内容。
- WEB-06：保存实际取得的内容以支持续读，失效或不可恢复时明确说明。
- WEB-07：批量请求分别报告结果，不能因为一项失败无说明地丢弃其余成功结果。
- WEB-08：网页文本是资料，不得自动提升为系统提示词模块。
- WEB-09：不静默切换付费后端；其他服务商仅保留适配边界。

## 7. 内部子 Agent 要求

- AG-01：主 Agent 在授权任务范围内自主判断是否委派，不要求用户每次主动点名。
- AG-02：不强制所有任务使用子 Agent，不允许通过委派扩大权限或任务范围。
- AG-03：默认通过 DSH 内部子 Agent 服务执行，不用终端静默启动外部 Agent 替代。
- AG-04：支持独立上下文和继承上下文；继承是创建时快照，不是实时同步。
- AG-05：提供启动、列出、状态、输出、完成通知、后续消息、中断、停止，以及后端支持范围内的继续执行。
- AG-06：支持并行、顺序协作和结果汇总，不将既定角色模板作为能力上限。
- AG-07：允许配置角色、模型、并发和递归限制；具体合理默认值由工程实现提出。
- AG-08：多写入任务需要目录或 worktree 等隔离与协调，避免无协调修改同一文件。
- AG-09：用户能够在 DSH 原生界面找到子会话、查看过程并在支持范围内介入。
- AG-10：停止、失败和正常完成不能混淆；主 Agent 负责检查、整合和验证结果。
- AG-11：外部 CLI 不参与默认路由，不因内部失败而自动接管。

当前工程范围默认：先完整实现内部子 Agent，外部 CLI 只保留适配边界与此前设计，不把多个外部产品的实际适配列为当前交付阻塞项。这是此次收敛采用的范围建议，不应冒充早期用户已经指定的外部后端清单。

## 8. 技能、提问、待办与现有插件

- NAT-01：沿用 DSH 技能的注册、发现、刷新和加载，不复制技能或维护 Nexus 技能白名单。
- NAT-02：用户按 DSH 规则新增技能后沿原生机制进入目录；自动出现的摘要不等于正文已经加载。
- NAT-03：尊重原生模型调用与用户调用标记。
- NAT-04：保留原生 ask_user_question 与 todo_write，不强行塞入 shell 或 agent。
- NAT-05：使用这些工具的复杂流程不自动写入基础提示词。
- NAT-06：现有插件提供的工具按自身机制保留；界面、安全、费用统计等不连带关闭。
- NAT-07：检查上下文压缩插件与新预设兼容性，尤其是只匹配原生预设 ID 的情况；不盲目叠加压缩机制。

## 9. 系统提示词规格

### 9.1 基础文本

```text
你是一名运行在 DeepSeek Harness（DSH）Agent 框架内的专业编程助手。

你通过读取文件、执行命令、编辑代码和创建文件，高效地帮助用户完成任务，并交付高质量的成果。
```

- PR-01：当前展示这份基础文本，不额外提供基础角色编辑器；此为保持原始范围的工程默认。
- PR-02：不额外加入“回复简洁”、强制规划、固定审查等行为准则。
- PR-03：不复制 Pi 的用户 AGENTS.md 或 APPEND_SYSTEM.md。
- PR-04：工具信息、使用说明和技能沿各自机制提供，不在基础文本中手写重复清单。

### 9.2 附加提示词模块

- PR-05：用户可创建和编辑模块、勾选并排序，保存 Nexus 默认组合或用于当前会话。
- PR-06：选中模块与基础文本进入同一系统指令层，不作为普通用户历史消息或工作区说明注入。
- PR-07：检查实际请求角色或适配器等价表示，不能凭 UI 标题证明系统级注入。
- PR-08：文本按字面处理，不默认执行模板或解析花括号中的宿主变量。
- PR-09：排列顺序不产生更高的新指令等级；系统级不保证覆盖服务商规则、权限或模型行为限制。
- PR-10：不能为实现基础与附加内容而清空第三方插件、工具正常贡献的系统说明。
- PR-11：原生 AGENTS.md 继续独立提供工作区指导，不与这个功能混为一谈。

### 9.3 生效与恢复

- PR-12：支持共享模块库、Nexus 默认组合及会话单独覆盖。
- PR-13：保存默认组合供新会话使用，不静默改变已有会话的生效内容。
- PR-14：明确应用到当前会话后，从下一次模型请求开始更新，不要求重新开会话。
- PR-15：不改写已发出的请求，不强制中断进行中的任务。
- PR-16：已有会话和子 Agent 保留已生效的提示词内容，不能只保存会被编辑或删除的模块引用。
- PR-17：会话恢复使用已生效内容；默认组合后续修改不偷偷改变历史会话。
- PR-18：默认不替用户启用额外行为模块。

## 10. 控制台界面

- UI-01：提供 Nexus 统一入口和公共导航，不替换整个原生布局或设置。
- UI-02：子页面按提示词、工具、终端、子 Agent、集成等功能组织，保持 DSH 主题和反馈一致。
- UI-03：当前不提供装配方案管理页或 Nexus／原生／关闭选择矩阵；工具页配置的是行为参数，不是任意功能组合。
- UI-04：不堆放没有实际功能的占位页面，不为预留扩展制造一套额外平台。
- UI-05：能复用或链接的原生设置优先复用，不重复维护账号配置。

提示词页面必须有：基础文本展示、模块创建与编辑、勾选、排序、拼接预览、保存默认组合、应用到当前会话。

提示词页面明确不提供配置版本号、版本差异对比或“有更新可用”提醒。预览不是实际生效证明，注入正确性由测试验证，不额外强加版本管理 UI。

## 11. 状态、数据和异常边界

| 情况 | 必须的行为 |
| --- | --- |
| 保存失败 | 明确反馈，不把未保存内容标为已应用 |
| 应用提示词 | 下一请求使用完整新组合，不出现半更新内容 |
| 已有会话恢复 | 恢复已生效提示词；所需运行能力缺失时明确报告 |
| 后端或依赖不可用 | 不伪造可用状态，不静默换实现或账户 |
| 文件已变化 | 不静默覆盖，给出重新观察和恢复方式 |
| 图片模型不支持 | 明确说明，不将路径返回当作已读取图片 |
| 停止尚未确认 | 不宣称进程已经退出 |
| 输出或网页被截断 | 说明已取得范围与可用续读方式 |
| 子 Agent 异常 | 向父任务返回可行动的信息，不伪装为成功 |
| 第三方仅适配原生预设 | 报告并检查兼容性，不以未封禁代替验证 |
| 关闭会话或卸载插件 | 按所有权完成清理或明确报告无法完成，不留下无管理执行 |

具体存储结构、工具字段名、错误代码、分页格式、合理资源上限由工程师依据 DSH 接口制定并写入实施计划。用户不需要决定所有这些技术细节。

## 12. 技术约束与工程选择

- 已检查的本机 DSH CLI 包为 `0.2.1-rc.2`，不能据此假定其他运行实例版本一致。
- 使用 TypeScript 与 DSH 插件契约，浏览器侧沿用宿主 React、主题与槽位机制；这是基于现有环境的工程选择。
- 注册和清理遵守 Cordis 作用域，工具及提示词贡献只作用于 Nexus 目标会话。
- 优先复用现有抽象，不为当前固定组合提前实现依赖图编辑器、装配 DSL 或动态下载模块。
- 不直接手改用户 Profile 文件，不修改安装目录，不硬编码密钥、私有地址或环境路径。
- 先定义工具契约和行为测试，再实现；包装不能绕过原生执行链。
- 真实阻塞，例如当前接口无法落实权限或恢复语义，应说明证据并提出必要取舍；普通工程默认不再逐项追问。

## 13. 验收标准

| ID | 验收情景与期望 |
| --- | --- |
| AC-01 | 一次安装后能在 DSH 使用一个独立 Nexus 预设，原生预设不被改写 |
| AC-02 | Nexus 核心工具正确可见，被替代原生入口不重复泄漏，第三方工具未被白名单屏蔽 |
| AC-03 | read 分页读取文本，并向支持图片的模型实际提供图片附件 |
| AC-04 | 多处编辑按契约处理，文件变化、匹配失败和编码问题不造成静默覆盖或不明部分修改 |
| AC-05 | 普通 shell 调用相互独立；显式持久终端能保留状态并接收输入 |
| AC-06 | 后台与交互任务可查状态、续读输出、停止和清理；异常与退出状态真实 |
