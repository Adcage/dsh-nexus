# DSH Nexus 自由装配扩展设计（后置）

**状态：后续扩展草案，不属于当前开发范围。**

用户要求先回到单预设核心方案，自由装配与多预设后续再做。以下保留此前讨论，不代表当前交付要求；其中历史状态和未决项也仅描述该扩展。当前实施依据为 `../2026-10-31-dsh-nexus-design.md`。

本文定义要构建的产品、行为边界与验收要求，不是讨论纪要，也不是实施计划。用户对局部讨论的认可不代表已经批准本规格全文。尚未完成独立的可规划性检查；在本规格获得完整批准前，不编写产品代码、不搭建工程、不安装依赖。

讨论依据见：`docs/plans/2026-10-31-dsh-nexus-design.md`。该文件保留为讨论记录，不作为最终需求来源。

## 1. 意图与问题

用户希望保留 DeepSeek Harness 的模型接入、会话、原生界面和插件生态，同时改善模型使用工具的方式。

当前痛点是部分原生工具划分过细、同类入口较多。例如文本与图片读取分别注册，让模型承担不必要的工具选择。目标不是机械追求最少的名称，而是让能力边界清楚、参数自然、执行可靠，减少无关和重复的工具定义。

项目随后明确为 `dsh-nexus`：一个可按个人习惯装配能力的 DSH 工作台。当前用户采用的组合应成为一套可用方案，而不是强迫所有使用者接受的唯一工作方式。

## 2. 目标、非目标与不可接受的结果

### 2.1 目标

- G1：一次安装一个插件包，通过内部模块组合功能。
- G2：用户可以保存多套装配方案，并在 DSH 中以预设形式选择。
- G3：提供精简的 Nexus 工具接口，优先复用 DSH 的运行基础设施。
- G4：通过原生 DSH 子会话保持子 Agent 的过程可见、可介入。
- G5：使用极简基础提示词，并提供真正的系统级附加提示词配置。
- G6：在统一控制台内按功能提供子页面，方便后续扩展。
- G7：保留第三方插件正常提供的工具和功能。
- G8：完整目标按步骤实现和验证，基础部分完成不等于整体交付。

### 2.2 非目标

- 不创建另一套 Agent 框架、插件市场或通用远程模块执行系统。
- 不修改原生 DSH 预设，不直接修改安装目录。
- 不为每个 Nexus 功能分别发布必需安装包。
- 不在当前范围内接入其他联网服务商，仅预留后端适配边界。
- 不接管用户安装、启用第三方插件的决定。
- 不自动安装、升级或登录外部 CLI。
- 不在基础提示词中固化一套强制规划、固定审查或其他复杂工作流程。

### 2.3 不可接受的结果

- UI 显示模块已关闭，但相关 Nexus 工具仍被默认提供给模型。
- 为了只显示核心工具而屏蔽用户安装的第三方工具。
- 把用户勾选的系统提示词作为普通用户消息发送，却标称同等系统优先级。
- 新预设导致原生预设或其他装配的工具、提示词、配置被意外改变。
- 为减少工具数量，丢失文件保护、权限处理、日志恢复或进程清理。
- 用外部 CLI 静默替代内部子 Agent，导致过程在 DSH 中不可见。
- 把工具停止运行、没有输出或发送了停止请求当作成功完成。
- 将上下文压缩、权限与安全机制当作普通工具一起移除。

## 3. 用户场景

### 场景 A：采用当前用户的开发组合

用户安装 Nexus，选择包含统一文件工具、`shell`、`web`、`agent` 和原生技能、提问、待办的装配。模型不再同时收到这些能力被替代的原生重复入口，但其他插件提供的工具继续按自身机制可用。

### 场景 B：采用不同工作习惯

另一位用户可以保留部分原生能力，只采用所需的 Nexus 模块。装配结果保存为自己的预设，不要求重装插件或修改其他人的组合。

### 场景 C：配置系统级提示词

用户在提示词模块库中编辑内容，为某个预设选择默认组合；也可以对当前会话使用不同组合。附加内容与基础提示词处于同一系统指令层，而不是依赖 AGENTS.md 或某条聊天记录维持。

### 场景 D：自主委派并观察过程

主 Agent 在授权任务内自主安排内部子 Agent。用户能够通过 DSH 原生会话界面找到子任务、查看内容、补充要求和停止执行。主 Agent 接收结果后继续整合及验证。

## 4. 产品结构与职责

Nexus 由一个插件包提供宿主侧功能和浏览器侧界面。

### 4.1 宿主侧职责

- 管理装配方案及其 DSH 预设绑定。
- 根据装配启用模块，在对应作用域注册工具和系统提示词贡献。
- 管理 Nexus 拥有的执行句柄、结果和配置。
- 调用 DSH 原生文件、联网、技能、子 Agent、设置与存储能力。
- 提供界面所需的受控配置访问，不向模型默认暴露系统指令管理权限。

### 4.2 浏览器侧职责

- 提供一个统一入口和一致的导航外壳。
- 各功能分别配置，不形成一个巨大表单。
- 清楚表达当前编辑的是装配默认值还是会话覆盖。
- 提供提示词模块管理、勾选、排序和组合预览。
- 复用 DSH 主题与界面扩展机制，不替换整个应用布局。

### 4.3 与 DSH 的责任划分

Nexus 负责使用方式和接口，不另行复制一套模型循环、会话存储或权限体系。对原生服务的复用必须保留其执行链，不能为包装工具而绕过审批、观察策略或资源所有权。

## 5. 核心逻辑对象

以下定义对象责任，不冻结具体数据库或 API 字段。

| 对象 | 必须表达的内容与责任 |
| --- | --- |
| 功能模块 | 身份、提供的能力、可配置项、依赖与清理行为 |
| 装配方案 | 名称、模块选择、模块配置、默认提示词组合及对应预设身份 |
| 提示词模块 | 名称与正文；只有明确选择的内容参与注入 |
| 提示词组合 | 模块选择及排列顺序 |
| 会话绑定 | 使用的装配以及会话自己的提示词选择与生效内容 |
| 受管执行 | 所属会话、模块、状态、输出与可用控制操作 |

对象必须有稳定的内部身份，不能把可编辑的展示名称直接当作运行中执行或恢复关系的唯一键。此为工程设计选择，不引入用户可见的配置版本管理。

## 6. 功能要求

### 6.1 模块化装配

- ASM-01：模块来自同一个插件包，用户无需逐个安装。
- ASM-02：支持保存多套装配方案，并提供对应 DSH 预设。
- ASM-03：装配只影响自身作用域，不修改原生预设或其他装配。
- ASM-04：启停必须影响对应功能的实际注册或贡献，不能只隐藏 UI。
- ASM-05：其他第三方插件不被纳入 Nexus 的默认工具封禁列表。
- ASM-06：不能因为关闭一个包装工具，就全局禁用被其他会话使用的底层服务。
- ASM-07：`read`、`write`、`edit` 分别装配，允许 Nexus 与原生实现混用；Nexus 的 `read` 内部统一处理文本和图片，不拆成两个入口。
- ASM-08：`shell`、`web`、`agent` 分别作为统一入口模块装配；内部能力与参数在模块内配置，不重新拆成多个模型工具。
- ASM-09：技能、结构化提问、待办分别选择是否接入原生能力。
- ASM-10：有 Nexus 替代实现的能力提供“Nexus 实现／DSH 原生实现／不在该方案中提供”三种选择；只接入原生能力的项目提供启用与停用。
- ASM-11：上述选择只处理该方案中的目标能力，不接管第三方插件提供的工具。
- ASM-12：修改方案的模块选择、工具实现和后端配置，默认只影响之后创建的新会话；已有会话继续使用创建时的装配，不静默跟随修改。
- ASM-13：会话需保留恢复实际装配所需的配置，而不能只保存一个会被修改的预设名称或 ID；从历史恢复后仍使用原组合。该要求保存的是功能选择和配置，不是为每个会话保留一套旧插件代码。
- ASM-14：装配修改不得打断已有会话的终端、后台任务或子 Agent。
- ASM-15：提示词保留第 7.3 节的显式应用操作，从下一次模型请求开始更新；该操作不顺带切换工具和后端。
- ASM-16：删除方案及其对已有会话的影响仍按第 12 节确认。

### 6.2 当前用户的默认工具方向

| 接口 | 要求 |
| --- | --- |
| `read` | 统一文本和图片读取；内部识别类型；文本支持分页 |
| `write` | 创建或完整写入文件 |
| `edit` | 精确局部替换；支持同一文件一次提交多处修改 |
| `shell` | 一个入口覆盖普通、后台、持久及交互执行 |
| `web` | 一个联网入口，后端复用 DSH |
| `agent` | 一个内部子 Agent 委派及管理入口 |
| `skill` | 沿用 DSH 的发现和加载机制 |
| `ask_user_question` | 保留原生结构化提问 |
| `todo_write` | 保留原生待办 |

- TOOL-01：上述组合不是所有用户必须采用的唯一方案。
- TOOL-02：上述数量不是模型可见工具的全局上限，其他插件工具按自身作用域继续可用。
- TOOL-03：默认文件搜索交给终端，不新增一个强制合并的 `search` 工具。
- TOOL-04：如最终提供专用搜索选项，`glob` 与 `grep` 保持独立；是否提供按第 12 节确认。
- TOOL-05：文件观察、并发变更检查、原子修改及用户已有工作的保护不能丢失。
- TOOL-06：统一读取不能只返回图片路径，必须通过受支持的附件路径向可看图的模型提供图片；不支持时明确失败。

### 6.3 终端

- SH-01：默认 Git Bash，支持显式选择 PowerShell 7。
- SH-02：普通调用是独立进程，不隐式继承上一条命令的目录、变量或函数。
- SH-03：需要状态保留或连续输入时，显式创建持久终端。
- SH-04：后台运行与持久终端分别表达；独立进程也可以后台运行。
- SH-05：持久终端内部的目录变化不静默改变整个会话工作目录。
- SH-06：完整功能包括状态查询、输出续读、交互输入、停止与清理。
- SH-07：长输出保留可恢复日志，模型每次读取有边界。
- SH-08：区分启动失败、运行、正常退出、非零退出、超时、取消、停止中及确认结束。
- SH-09：禁止失败后静默换 Shell 重跑；可能已有副作用的命令不能未经核对自动重复执行。
- SH-10：必须实际适配 Windows。已检查的原生 `dsh-bash-local` 不支持 Windows，不能直接视为现成 Git Bash 后端。

### 6.4 联网

- WEB-01：复用 DSH 当前可用的搜索和抓取后端，不要求新增第三方搜索订阅或密钥。
- WEB-02：费用沿用当前后端规则，不将“没有新增第三方服务”表述为底层请求绝对免费。
- WEB-03：预留搜索与抓取后端的适配边界，不在当前范围实现其他服务商。
- WEB-04：提供搜索、页面获取、已获取内容续读及定位的统一使用方向；最终操作参数属于待完成的工具契约。
- WEB-05：返回可追溯来源、结果标识和截断信息；搜索摘要不能伪装为已读取原文。
- WEB-06：只能保存实际获得的内容，上游已经截断时不得承诺持有完整原文。
- WEB-07：网页内容是外部资料，不得自动提升为系统提示词模块。
- WEB-08：不得静默切换付费后端。

### 6.5 子 Agent

- AG-01：主 Agent 在授权任务范围内自主委派，不要求每次由用户主动点名。
- AG-02：不强制每个任务使用子 Agent，也不允许委派扩大任务或权限边界。
- AG-03：默认使用 DSH 内部子 Agent，保留父子关系、会话记录及原生界面入口。
- AG-04：独立上下文与继承上下文明确区分；继承是创建时快照，不是实时同步。
- AG-05：完整方向包含启动、列出、状态、输出、完成通知、后续消息、中断和停止，以及后端支持范围内的继续执行。
- AG-06：支持任务分工与协作；并行写入需要避免无协调地改动同一文件。
- AG-07：允许复用角色模板，也允许按任务直接描述职责，不将模板目录作为能力边界。
- AG-08：主 Agent 对整合和最终验证负责，子任务报告不能代替验收。
- AG-09：外部 CLI 是可选扩展，不参与默认路由，不因内部失败而静默接管任务。
- AG-10：若启用外部后端，需区分已安装、适配兼容、认证状态、任务能力和权限可落实程度；不为探测偷偷发起收费模型请求。
- AG-11：并发、递归及可用模型应有配置边界，具体值不在本规格中臆定。

### 6.6 原生技能、提问和待办

- NAT-01：技能沿用 DSH 原生注册、发现、刷新与加载，不复制技能内容或建立 Nexus 白名单。
- NAT-02：用户按 DSH 规则新增技能后，沿原生机制进入目录；摘要可见不等于正文已加载。
- NAT-03：保留原生模型调用与用户调用标记。
- NAT-04：保留结构化提问和待办，不强行合入终端或子 Agent 接口。
- NAT-05：使用这些能力的详细工作方法不自动扩写进基础提示词。

## 7. 系统提示词规格

### 7.1 基础文本

```text
你是一名运行在 DeepSeek Harness（DSH）Agent 框架内的专业编程助手。

你通过读取文件、执行命令、编辑代码和创建文件，高效地帮助用户完成任务，并交付高质量的成果。
```

- PR-01：不额外加入“回复简洁”等固定行为准则。
- PR-02：不自动加入强制规划、固定审查等流程。
- PR-03：不复制 Pi 用户目录内的 AGENTS.md 或 APPEND_SYSTEM.md。
- PR-04：工具元信息、工具贡献规则及技能由各自机制提供，不在基础文本中手写重复清单。

### 7.2 附加模块的身份

- PR-05：用户明确选择的模块与基础文本进入同一系统指令层，不作为普通用户历史消息或工作区说明注入。
- PR-06：必须检查实际请求角色或适配器等价表示，不能只凭 UI 标签证明系统级注入。
- PR-07：文本按字面处理，不默认执行模板或解析花括号中的宿主变量。
- PR-08：排列顺序不表示产生一个比其他系统内容更高的新等级。
- PR-09：系统级注入不承诺越过服务商规则、执行权限或保证模型绝对遵循。
- PR-10：不得通过清空全部系统提示词贡献来实现，以免丢失工具和第三方插件提供的说明。
- PR-11：AGENTS.md 继续沿 DSH 原生机制提供工作区指导，与该功能分开。

### 7.3 编辑与生效

- PR-12：支持共享模块库、每个预设的默认组合，以及会话单独覆盖。
- PR-13：保存默认组合供新会话使用，不静默改写已有会话正在使用的组合。
- PR-14：用户明确应用到当前会话后，从下一次模型请求开始使用新组合，不要求重新开会话。
- PR-15：已经发出的请求不被中途改写或强制中断。
- PR-16：子 Agent 默认使用创建时继承的组合，不因随后编辑库内容而悄悄改变正在执行的任务。
- PR-17：默认不替用户启用额外行为模块。

## 8. 界面规格

### 8.1 公共外壳

- UI-01：在 DSH 中新增 Nexus 统一入口，不替换整个原生布局或设置。
- UI-02：采用公共导航与分功能子页面，保持主题、布局和保存反馈一致。
- UI-03：子页面组织方向包含装配、提示词、工具、终端、子 Agent、集成；最终导航和视觉稿尚待设计。
- UI-04：不重复维护两套原生账号配置；可复用或链接的设置优先复用。

### 8.2 提示词页面

必须提供：

- 基础提示词展示。
- 提示词模块创建和编辑。
- 模块勾选及排序。
- 拼接内容预览。
- 保存为默认组合。
- 应用到当前会话。

明确不提供：

- 配置版本号展示。
- 配置版本差异对比。
- “有更新可用”等版本管理提示。

组合预览只表示编辑结果，不冒充真实模型请求。注入验证是实现验收要求，不因此强加一套版本管理 UI。

## 9. 状态、数据与异常边界

| 情况 | 要求 |
| --- | --- |
| 保存失败 | 反馈原因，不将未保存内容标为已应用 |
| 配置依赖缺失 | 明确失败，不显示虚假的可用状态；依赖交互细节待决 |
| 一个装配发生变更 | 新会话使用新组合；已有会话保留原组合，不污染其他装配或原生预设 |
| 恢复会话所需模块或后端已不可用 | 明确报告缺失或不兼容，不静默替换为其他实现 |
| 当前会话应用新提示词 | 新请求使用完整新组合，不使用半更新内容 |
| 已发出模型请求 | 保持该请求已构建的内容，不尝试中途改写 |
| 文件在观察后被外部修改 | 不无条件覆盖，遵守观察策略并给出恢复方式 |
| 图片模型不支持 | 明确解释，不把路径返回当作已看图 |
| 终端停止未确认 | 不能报告进程已经退出 |
| 联网失败 | 报告当前后端错误，不暗中更换收费渠道 |
| 已获取内容被截断或不可恢复 | 明确说明范围，不能伪装为完整 |
| 子 Agent 失败 | 向父任务提供可行动的失败信息，不当作成功结果 |
| 第三方插件仅适配原生预设 | 作为兼容性问题处理，不以“没有主动屏蔽”代替验证 |
| 多套压缩机制同时存在 | 必须检查重复压缩或上下文丢失，不默认叠加 |

存储与配置需复用 DSH 支持的服务，保留会话和装配作用域。具体表结构、普通内部标识和并发控制由工程实现决定，不引入用户可见的版本系统。

## 10. 技术约束与交给工程实现的决定

### 已知约束

- 已检查的本机 DSH CLI 包为 `0.2.1-rc.2`；其他运行实例仍需确认版本。
- 主要目标环境为 Windows，默认终端为 Git Bash，并支持 PowerShell 7。
- 需要宿主与浏览器两个入口，遵守 DSH 的设置、界面、作用域和清理契约。
- 不直接手改用户 Profile 文件，不在安装目录修改原生代码。
- 不硬编码密钥、私有服务地址或环境特定程序路径。
- 不把“未封禁第三方插件”当作兼容性已经通过的证明。

### 工程建议，不冒充用户已决定

- 使用与 DSH 插件接口一致的 TypeScript；浏览器部分沿用宿主 React 和主题体系。
- 通过包内声明式模块描述组织贡献和依赖，不运行用户随意填写的模块代码。
- 按装配作用域接入原生预设机制，不另建独立会话引擎。
- 用户输入的提示词使用字面系统段，避免原生模板插值导致文本改变或组装失败。
- 先定义工具契约，再按契约驱动行为测试；复用原生能力时不绕过执行链。

具体文件结构、工具字段命名、内部状态标识、日志分页格式、错误代码和合理资源上限，可由工程师依据现有接口制定并在实施计划中说明。若决定会改变功能范围、授权方式或用户可见行为，则需回到设计确认，而非当作普通技术细节处理。
